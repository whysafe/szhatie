# szhatie: gzip с нуля на C++20

Утилита сжатия, совместимая с gzip, написанная без zlib и сторонних библиотек: LZ77 с хеш-цепочками, коды Хаффмана с ограничением длины, формат DEFLATE (RFC 1951) и обёртка gzip (RFC 1952). Файлы, сжатые szhatie, распаковывает обычный `gzip`, а szhatie распаковывает файлы gzip. Это проверяется в CI на каждом коммите.

## Сравнение с GNU gzip

Замер из CI (Ubuntu 24.04, GitHub Actions). Размеры в байтах, в скобках время:

| Файл | Размер | gzip -6 | szhatie -6 | gzip -9 | szhatie -9 |
|---|---:|---:|---:|---:|---:|
| заголовки libstdc++ | 11 523 389 | 1 787 371 (0.25 с) | 1 789 278 (0.37 с) | 1 772 014 (0.63 с) | 1 780 324 (0.76 с) |
| лог nginx, 200 000 строк | 14 728 898 | 2 091 926 (0.29 с) | 2 078 000 (0.50 с) | 2 001 121 (1.23 с) | 2 052 829 (0.94 с) |
| исполняемый файл | 128 760 | 54 164 | 54 214 | 54 001 | 54 030 |
| случайные данные | 3 000 000 | 3 000 489 | 3 000 489 | 3 000 489 | 3 000 489 |

- **Размер.** Получается в пределах 0.1–2.6 % от gzip. На логе при `-6` szhatie сжимает даже немного лучше.
- **Скорость.** На `-6` szhatie медленнее примерно в 1.5 раза: в gzip десятилетия оптимизаций. Зато случайные данные не раздуваются, а уходят несжатыми блоками.

## Использование

```bash
szhatie access.log              # -> access.log.gz, исходник остаётся
szhatie -9v *.csv               # сильнее и с отчётом: размер, процент, время
szhatie -d access.log.gz        # распаковать
szhatie -t backup.gz            # проверить целостность (CRC-32 и длина)
szhatie -l access.log.gz        # имя в архиве, размеры, степень сжатия
tar cf - src | szhatie -c > src.tar.gz
```

```
$ szhatie -l access.log.gz        # из CI, тот же лог
      сжатый     исходный  сжатие  имя
     2052829     14728898   86.1%  access.log
```

## Как устроено

```
src/bits.hpp       побитовые запись и чтение, младший бит вперёд, как требует DEFLATE
src/huffman.cpp    длины кодов (package-merge), канонические коды, декодер
src/deflate.cpp    LZ77 и выбор типа блока
src/inflate.cpp    распаковка блоков всех трёх типов
src/gzip.cpp       заголовок, CRC-32, склеенные архивы
src/main.cpp       консольная утилита
```

**Поиск совпадений.** Хеш трёх байт указывает на последнюю позицию с таким же началом, а массив `prev` связывает предыдущие позиции в цепочку в пределах окна 32 КБ. Уровень задаёт длину просматриваемой цепочки (от 4 до 4096) и ленивое сопоставление. Найденное совпадение не берётся сразу, если со следующего байта есть более длинное.

**Коды Хаффмана.** В DEFLATE коды литералов и расстояний не длиннее 15 бит, а коды заголовка не длиннее 7. Обычный алгоритм Хаффмана такого ограничения не знает. Поэтому длины строит package-merge: он даёт оптимальный префиксный код с заданной максимальной длиной. Тест проверяет его на частотах Фибоначчи, которые дают самое глубокое дерево.

**Выбор блока.** Для каждого блока из 32 768 токенов считается точный размер в битах для трёх вариантов: динамические деревья с заголовком, фиксированные деревья или без сжатия. Пишется самый короткий.

**Распаковка.** Проверяется всё, что может прийти испорченным:
- переполненные и неполные деревья (неравенство Крафта);
- ссылки до начала данных;
- несовпадение LEN и NLEN;
- обрыв потока;
- CRC-32 и длина в трейлере.

Тест портит сжатый поток в 500 случайных местах и проверяет, что каждый раз выходит понятная ошибка, а не падение. В CI этот тест идёт под AddressSanitizer и UBSan.

## Сборка

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release      # GoogleTest скачивается автоматически
```

Нужен компилятор с C++20: GCC 11+, Clang 14+ или Visual Studio 2022. `-DSZHATIE_SANITIZE=ON` включает ASan и UBSan, `-DSZHATIE_TESTS=OFF` собирает только утилиту.

## Тесты

13 тестов GoogleTest:
- CRC-32 по контрольным значениям;
- ограничение длины кодов и полнота дерева;
- распаковка потоков zlib всех трёх типов блоков и gzip с именем файла (векторы получены из Python);
- отказ на испорченных данных и 500 случайных порч;
- сжатие и распаковка всех уровней на пустых, однобайтовых, повторяющихся, многоблочных и случайных данных;
- склеенные архивы с нулевым хвостом.

Отдельный шаг CI [scripts/interop.sh](scripts/interop.sh) сжимает корпус на уровнях 1, 6 и 9 и проверяет `gzip -t`, `gzip -dc | cmp` и обратное направление.
